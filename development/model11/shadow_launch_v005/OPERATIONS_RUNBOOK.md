## P3: independent storage and namespaces

Select a **new, independently owned private storage root** for this Shadow only. The actual path and `storage_identity` remain null in the public template. Do not point it at the production SQLite DB, any production disk directory, an existing A/B store, the canonical source, or a public GitHub tree. The store's root ownership marker, namespace and identity/config fingerprints must be reviewed before initialization. An unowned nonempty root, symlink, unexpected existing content, identity mismatch, or silent root/namespace change is STOP.

Maintain separate artifact classes and references:

| Artifact class | Required separation |
| --- | --- |
| Original source capture / normalized input evidence | Immutable bytes and SHA; original source acquired/available/revision metadata retained |
| Original predeadline forecast | Immutable bytes, its own SHA/model/code/config references and generation time; never edited after results |
| Save/readback receipt | Separate byte/size/hash/clock references and ledger state; receipt presence alone is not independent authenticity |
| Result observations | Append-only versions with source identity, availability/revision and final status; no prediction rewrite |
| Settlement/evaluation ledgers | Separate derived records referring to an explicitly selected final result version and original forecast hash |
| Daily audit and STOP evidence | Separate append-only observations; unknown, partial or failed states retained |

The local store uses `OWNER.json`, `ledger.sqlite3` and permitted SQLite sidecars, `artifacts/<race-key>/{input.raw,forecast.raw,receipt.json,completion.json}`, `results/<race-key>/<result-sha>.raw`, `audits/<kind>/<identity-sha>/<report-sha>.raw` with a separate `.receipt.json`, and a durable `STOP.json`. Audit kinds are `DAILY_SETTLEMENT` and `OPERATIONS_AUDIT`. These are relative names, not an actual approved location. Final-result selections are append-only ledger entries. The settings' configured opaque `storage_identity` and the store-generated ownership `storage_id` are distinct: record and bind their relationship during the separately authorized initialization, and require it on later readback/restart. The runner uses `bind_context` to pin the actual owner ID plus approved config/storage/artifact fingerprints in the store. A settings fingerprint alone does not prove the same physical store still exists.

The final `STORAGE_CONTRACT.md` controls the exact allowed layout. Local immutable daily/operations report persistence is implemented with `save_audit_report(kind, identity, raw_bytes, metadata)` and `read_audit_report(kind, identity, report_sha256)`. `daily_settlement` saves and verifies a separate report/receipt; computation alone is not a successful settlement save. STOP blocks audit writes too. Do not add undeclared files to the strictly owned root. A local saved/readback report, folder layout or successful self-hash must not be reported as external archiving, off-host durability, or an independently authenticated predeadline record. Backup/retention, host loss recovery, external timestamping and any off-host transfer still require an approved private design and individual scope. Do not publish captures, actual forecasts/results, private approval artifacts, personal identifiers, credentials, secrets, source authentication URLs or actual backup bytes.

Race identity is unique across model versions within the third research namespace. A new model hash does not authorize another first forecast for the same race. Existing committed receipts are read back; duplicates are not replayed. A reserved but uncertain race remains HOLD after a crash/restart; model changes, a fresh process or a changed directory name must not be used to bypass that boundary. Preserve partial files and uncertain ledger entries for review instead of cleaning them up or retrying automatically.

## Implemented local CLI and API reference

The command prefix is `python -B -m model11.shadow_launch.cli`. The table is a future operator reference, **not execution authorization**. All filenames below are placeholders for separately approved private local files; no actual path, artifact, ACK or enabled setting has been supplied here.

| Subcommand | Explicit inputs | Actual behavior / limits |
| --- | --- | --- |
| `preflight` | `--config CONFIG --artifacts ARTIFACTS --operator-ack ACK` | Local files and structural gate only; no source/store initialization. Disabled default short-circuits. An allowed result is not authenticated GO. |
| `run` | Same context plus `--captures CAPTURE_LIST` | One explicit local JSON list of materialized captures; per-race reservations/commit/readback. Batch completion is not a claim that every race committed. |
| `watch` | Same context plus `--input-dir SPOOL --poll-seconds SECONDS`, optionally bounded `--max-iterations COUNT` | Foreground local `*.json` capture spool reader only; no HTTP fetch, scheduler registration or automatic startup. Source files must be immutable; changed/symlink files cause STOP. |
| `result` | Same context plus `--outcome OUTCOME` | Separate validated result ingestion/versioning; original forecast stays immutable. |
| `settle` | Same context plus `--date YYYY-MM-DD --selection SELECTION` | Selection JSON maps every committed local forecast for that date to an explicit final-result SHA. Persists a separate daily report/receipt; missing/extra/local-uncertain scope HOLDs. |
| `stop` | `--config CONFIG` only | Targets an already owned independent Shadow store and sets durable STOP; it is neither a Production stop nor a flag-clear/resume command. Verify the target first. |
| `demo` | `--output-dir NEW_DEMO_DIRECTORY` | Only the shipped invented 2099 fixture, a new owned temporary/demo output and fake clock; no live use. |

Capture files use the exact source envelope in `SOURCE_MAPPING.md`, replacing the in-memory `payload_bytes` field with `payload_bytes_b64`; the CLI decodes those exact original bytes. A list is required by `run`; `watch` expects one such object per immutable `*.json` file. Mapping approval, capture origin, official parsing and scheduled-race completeness remain unverified by this file format. The result-selection file is an explicit `{race_id: full_final_result_sha256}` mapping, not a request to choose the latest result automatically.

`--simulation-now` is allowed only for SIMULATION fixtures. PRIVATE_SHADOW uses the actual aware execution clock; a private clock override is rejected. `SIGINT`/`SIGTERM` request durable STOP and shutdown; they do not grant automatic restart. The CLI prints status summaries, not raw private bytes. Inspect every per-race status and stored receipt; a `RUN_COMPLETE`/`WATCH_STOPPED` wrapper or process exit alone is insufficient evidence of successful forecasts. The detailed `ShadowRunner.run_race`, `ingest_result`, `daily_settlement`, `request_stop` and `shutdown` APIs return the local reports used by an approved private operator tool.

There is no separate CLI readback subcommand. The owned-store APIs `readback(race_id)` and `read_audit_report(...)` provide private bytes/receipts for independent verification after the approved operation; do not print or publish those bytes. `save_audit_report("OPERATIONS_AUDIT", identity, raw_bytes, metadata)` is an explicit separate API, not automatic daily monitoring. If STOP is already set, preserve the first STOP receipt and use separately approved private investigation notes rather than expecting a post-STOP audit-write exception.

## Separate result ingestion, settlement and daily audit

Result ingestion is separate from forecasting. Append original result versions with source availability/revision/final status; result updates never edit the original forecast. Explicitly choose the approved final result version for a settlement run. `select_result` pins the observed result-revision frontier; a later final invalidates silent reuse of that selection, even with tied timestamps. Missing, contradictory, multiple ambiguous finals, an impossible refund/winner combination or unknown payout is UNVERIFIED/HOLD; no absent result or failed read is a zero return. A correction requires a new explicitly reviewed selection event/report version; it never overwrites an earlier selection, report or forecast. A blocked reselection is HOLD, not permission to edit a ledger or reuse an old event ID.

`daily_settlement(date, selection, operator_ack=...)` requires its selection mapping to match **all locally committed store forecasts for that date**, with no extras; unresolved stored forecasts prevent a complete settlement claim. It saves exact report bytes and metadata containing the selected result-SHA map through `save_audit_report("DAILY_SETTLEMENT", date, ...)`. The store verifies that map against explicit selections and their result frontiers again inside its exclusive save transaction. `AUDIT_SAVED`/idempotent `AUDIT_DUPLICATE` plus `read_audit_report` byte/hash/receipt agreement provides implemented **local** persistence/readback. Do not describe this scope as all official scheduled races: official schedule coverage remains **UNVERIFIED** until independent scheduled-race evidence is supplied.

Keep separate original-input, original-forecast, receipt, result and settlement hashes. Report ordinary five at 500 yen and each six-ticket BOX at 600 yen as separate standalone methods, plus original BET/SKIP and any independently named proposed overlay.
