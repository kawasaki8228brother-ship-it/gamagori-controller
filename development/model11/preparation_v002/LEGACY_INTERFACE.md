# Frozen Model 1.0 / BOX Ver.1 comparison interface

Status: **PROPOSED offline evaluation adapter**. No formal Model1.0, Human BOX
Ver.1, or Mechanical BOX Ver.1 selection algorithm is implemented, inferred,
trained, or substituted. No real frozen outputs or reference profiles are
bundled. Real comparison remains OPEN pending HQ14's private evidence review.

The adapter reads only supplied in-memory values. It does not connect to any
service, discover credentials, receive a production export automatically, or
write source records. Reports contain fixed reason codes and digests, not raw
received bytes, receipt bodies, arbitrary evidence text, URLs, or paths. Root's
local JSON CLI can consume the JSON-safe envelope format below; source data
must stay in HQ14's private environment and must not be committed publicly.

## API and trust boundary

```python
validate_frozen_predictions(envelopes: list, profiles: dict) -> dict
compare_frozen(research_records: list, envelopes: list, profiles: dict) -> dict
make_synthetic_legacy_fixture(research_records=None, *, synthetic_only=False) -> dict
```

Validation returns metadata only. It does **not** export parsed ticket records
as training input. Comparison privately decodes the verified bytes and uses
fixed ticket sets solely for evaluation. `research_records` are original
engine/walk-forward records with their original `source=MODEL11_RESEARCH`,
`prediction_sha256`, and embedded `actual`. Their source is never rewritten to
A or B. The hash check reconstructs the original forecast by removing `actual`
and `prediction_sha256`, resetting outcome-specific `first_course` to null,
then applying the existing candidate's `canonical_hash`. Research metadata
itself still needs independent provenance review.

`LOCAL_MATCHED` proves agreement of locally supplied bytes, decoded content,
profile binding, and self-reported chronology metadata. It is **not** a claim
that the bytes existed before the deadline or were generated by the frozen
production algorithm. Even if a user rewrites bytes, recomputes the digest,
and fabricates consistent receipt times, external authenticity stays
`UNVERIFIED`. No cryptographic signature or independently queried archive is
provided. The code cannot verify human review merely from a review identifier.

Other results are OPEN (required comparison/reference evidence absent), HOLD
(inconsistent or invalid evidence), or UNVERIFIED_MONEY (matched tickets but
insufficient settlement information). No statistical performance PASS,
legacy reproduction PASS, deployment GO, or automatic promotion is emitted.

## Exact received-byte envelope

An envelope is JSON-safe; base64 is a **transport encoding, not encryption**.
The program does not regenerate the claimed raw bytes from parsed content.
It decodes the supplied base64, checks exact length and full SHA-256, then
parses those bytes directly as UTF-8 JSON. The raw JSON must be an object;
duplicate keys and NaN/Infinity are rejected. A PROPOSED local resource limit
is 2,000,000 decoded bytes. Optional `parsed_prediction` is a sidecar and must
match the decoded typed JSON tree. It is never used in place of the raw body.

```json
{
  "source": "A",
  "raw_bytes_b64": "<base64 of exact received prediction JSON bytes>",
  "raw_byte_count": 1234,
  "raw_sha256": "<64 lowercase hex digits>",
  "received_at": "2099-01-17T12:02:00+09:00",
  "predeadline_evidence": {
    "kind": "HASH_RECEIPT",
    "artifact_id": "SYNTHETIC-RECEIPT-NOT-AUTHENTICATED",
    "source": "A",
    "race_id": "20990117_GAMAGORI_1R",
    "target_date": "2099-01-17",
    "deadline": "2099-01-17T13:00:00+09:00",
    "generated_at": "2099-01-17T12:00:00+09:00",
    "raw_sha256": "<same full digest>",
    "recorded_at": "2099-01-17T12:01:00+09:00"
  }
}
```

Placeholders are documentation, not executable evidence or real outputs.
Source, race/date, deadline, generated-at, and digest must match the decoded
prediction exactly. Times require explicit known offsets and at most six
fraction digits; naive times and `-00:00` are rejected. Required ordering is
`generated_at <= recorded_at < deadline`. If supplied, `received_at` must be
at or after recorded-at and may be after the deadline: a later local transfer
cannot itself establish earlier existence. Generation and deadline must fall
on target-date in JST. Receipt authenticity is always a separate OPEN issue.

## Per-source reference profiles

`profiles` has independent `A` and `B` keys. Each value is another exact-byte
frame (`raw_bytes_b64`, `raw_byte_count`, `raw_sha256`) plus a restricted
`review_evidence_id`. Its decoded JSON is:

```json
{
  "schema": "FROZEN_SOURCE_PROFILE_V1_PROPOSED",
  "source": "A",
  "profile_id": "SYNTHETIC-A",
  "model_version": "1.0",
  "box_version": "1",
  "classification": "SYNTHETIC_ONLY",
  "reference_description": "SYNTHETIC_NOT_FORMAL_LOGIC"
}
```

For HQ14 private external inputs, classification is `LOCAL_PRIVATE_EXTERNAL`
and reference-description is `SUPPLIED_FROZEN_OUTPUT_REFERENCE`. This is a
source/output-contract profile, **not** the formal prediction algorithm's
source-code bytes. It does not reproduce or authenticate formal logic.
Profiles A/B cannot substitute for one another. Review/profile/artifact/race
identifiers use bounded identifier characters, not arbitrary paths, URLs,
tokens, or evidence prose. Formal versions are accepted only as exact labels
`model_version=1.0` and `box_version=1`; those labels are not verification.

## Raw prediction content

The decoded prediction has exactly these top-level fields:

```
schema = FROZEN_OUTPUT_V1_PROPOSED
classification = SYNTHETIC_ONLY | LOCAL_PRIVATE_EXTERNAL
source = A | B
profile_id, reference_sha256, model_version, box_version
race_id, target_date, deadline, generated_at
methods = {normal5?, human_box?, mechanical_box?}
```

At least one method is required. Profile fields and classification must bind
to that source's decoded reference. Unknown top-level and method fields are
rejected; outcome/payout data do not belong inside a frozen prediction.

- `normal5`: `tickets` containing five unique ordered triple strings.
- `mechanical_box`: three unique `boats` and all six ordered permutations as
  `tickets`.
- `human_box`: the same six-ticket structure, plus supplied `core` (two boats),
  `insertion` (third boat), and `normal5_frequencies` with string keys `1`–`6`.
  Core and insertion must describe the supplied three boats. Frequencies must
  equal each boat's number of appearances in that same source's normal five
  tickets. This checks arithmetic consistency of supplied metadata only; it
  does not infer how a formal Human BOX should be chosen. Human metadata
  requires that source's normal5 output in the same frozen body.

Optional `bet_decision` may be BET or SKIP. The comparison reports standalone
fixed-ticket ledgers regardless of that decision; it does not reinterpret
historical decisions or actual purchases. Action-versus-SKIP performance is
available separately in the existing research evaluator. Other old-output
schemas require a reviewed private conversion before use; the adapter does
not silently translate unknown versions.

## Matched comparisons and missingness

Output keys are `comparisons.research_vs_A` and `comparisons.research_vs_B`.
Each has three independent methods: `normal5`, `human_box`, `mechanical_box`.
The research Human-style candidate is explicitly **not** formal Human BOX
reproduction. It is compared with externally supplied Human BOX tickets as a
separate hypothetical strategy. There is no pooled A/B result, cross-source
training input, aggregate mixed-method stake, or claim that supplied sources
were independently generated.

Matching requires exact race/date and equivalent deadline instant. Both
prediction generation times must precede that deadline. Duplicate source/race/
date frozen records are all held; duplicate research race/date records are all
held. No first-copy/last-copy winner is selected. Extra unmatched frozen races,
wrong outcome identities, hash failures, date/deadline differences, missing
source profiles, and missing methods remain visible. Each method reports
expected, paired, and missing-or-invalid N plus fixed issue codes. A partial
cohort stays OPEN/HOLD even when its known subset has descriptive numbers.
Final outcomes require a known timezone-aware `available_at` at or after the
race deadline. Missing, naive, or predeadline outcome availability is HOLD;
the evaluator does not silently admit an impossible early result.

Each paired normal5 ledger costs 500 research yen; each paired BOX ledger
costs 600. Shared tickets in different ledgers are not combined. Official
`payout_per_100` is returned once for the selected winning ordered ticket.
Selected refunded tickets return 100 each. Hit rate is distinct from profit.
Missing refunds or a missing selected winner's payout makes money unknown;
it is not assumed zero. A known miss needs no winning payout to establish
selected payout zero. A refunded winning result is inconsistent and held.
Return-rate is returned-yen/stake and ROI is net-yen/stake. Empty cohorts have
null rates/totals. Money totals and differences carry known-money counts and
describe only their explicitly matched subset. No superior-model conclusion
follows from a positive synthetic difference.

## Synthetic demonstration and private evidence still required

The helper requires `synthetic_only=True`. With existing records, every race
must have a 2099 date and `2099MMDD_GAMAGORI_nR` identifier; it verifies the
original forecast digest and leaves records byte-semantically unchanged.
With no records it invents three 2099 examples. It returns `envelopes`,
`profiles`, `research_records`, and explicit `SYNTHETIC_ONLY` warnings.
Dummy A and B tickets are independently hard-coded fixture patterns; neither
is copied from research selections or claimed as a Model1.0 forecast. Every
profile states `SYNTHETIC_NOT_FORMAL_LOGIC`. Version labels exercise the input
contract only. Synthetic evidence receipts are self-reported and unauthenticated.

HQ14 must privately supply or verify: authentic fixed predeadline A/B outputs,
the exact received bytes/digests, source-specific profile identities, reviewed
receipt evidence of existence before each deadline, official outcome/refund
identity, complete race coverage, and the mapping from any historic output
format. Codex does not request real raw records, original credentials, or
production access. Without this evidence real comparison remains OPEN.

Reproduce only the synthetic checks:

```sh
python -B -m unittest discover -s tests -p test_preparation_legacy.py -v
```

All local checks remain separate from Claude review, Andy GO, production
application, natural-run verification, and CLOSE. `production_go` is always false.
