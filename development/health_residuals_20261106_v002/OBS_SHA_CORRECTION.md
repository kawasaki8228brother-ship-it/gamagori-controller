```
d462767f4448e28fc735df7363fb6f54a577e014607d5ec3b2fb1a75137c5e7f
```

この値は64桁の小文字16進数である。形式検査はPASS_FORMAT_ONLYであり、仕様原本bytesからの再計算・独立照合は未実施。値の外部真正性と正確な仕様版への独立した対応確認はUNVERIFIEDのまま保持する。これは**専用OBS契約のSHAではない**。

## v001原文との関係

v001で受領・記録した値は、当時の原文として変更しない。

```
d462767f4448e28fc735df7363fb1a75137c5e7f
```

旧値は40桁で、受領ラベルはSHA256だった。v001が記録した桁数不一致・アルゴリズムUNVERIFIEDという歴史上の観測も保存する。旧値を別アルゴリズムへ読み替えたり、不足部分を推測したり、旧ファイルを訂正後の値で上書きしたりしない。

本記録は「旧い関連A予測仕様参照の訂正」という関係を新規ファイルで追加する。既存 `development/health_residuals_20261105_v001/obs_qa.py` の `related_A_reference` 出力が40桁の旧値を保持するのは、v001の原本・挙動を保全するためである。今回の訂正を無視したという意味ではない。

v001のQA結果を参照する際は、本v002訂正記録を併記する。v001の歴史値を現在のA予測仕様参照として単独で引用しない。逆に、新64桁値をOBS契約の根拠として用いない。ランタイム定数やQA挙動の更新は今回の範囲外であり、別の変更として審査が必要になる。

## OBS契約について変更しない判断

専用OBSの全文・版・SHAは独立照合されていない。A予測仕様の参照SHA訂正によって、次の判断は確定しない。

- payload内の `event_uuid` が必須か：UNVERIFIED。
- 列側 `event_uuid` だけで適格か：UNVERIFIED。
- RUN_STARTで空の `source_evidence` 配列を許容するか：UNVERIFIED。
- `source_evidence` プロパティ欠損が正式違反か：UNVERIFIED。

したがって、payload UUID欠損や空配列を一律の正式FAILへ変更しない。列UUIDからの自動補完、契約フィールドの新設、既存イベントの修正、LOCK有効性の変更も行わない。
