PER-TARGET SCHEMA AND CLASSIFICATION
id: fixed target label, never its URL.
tls: CONNECTED, CERT_REJECTED or OTHER_FAILURE.
http: FIRST approved target response status, or null before any response.
verify_code: int from an actual ssl.SSLCertVerificationError, or null.
verify_message: only that exception's verify_message attribute, or null.
why: a fixed reason enum when relevant; never str(exc), headers or proxy values.

1. ANY HTTP response from the approved target, including 403, 404, 5xx or a redirect,
   proves that target's TLS connection succeeded: CONNECTED. A later redirect scope
   block, timeout or certificate error does not erase the first response. http is
   the first status, not necessarily the final status. Verification fields are null
   for this already-proven CONNECTED result; no later-hop error is misattributed.
2. Before a response, traverse __cause__ AND __context__ with cycle detection, at
   most 16 nodes and depth 8. Decisions use isinstance, never exception text.
   ProxyError, TimeoutException, gaierror and ScopeBlocked take priority and produce
   OTHER_FAILURE. A proxy CONNECT 403 is not a target response: OTHER_FAILURE/http=null.
3. CERT_REJECTED requires a real SSLCertVerificationError and int verify_code in
   {2,19,20}. Missing/non-int/bool codes, other codes (including 18,10,62,64), an
   ambiguous chain, traversal limit or a string merely mentioning certificate
   verification failure produce OTHER_FAILURE. Codes describe the failure class;
   they are not independently a proof about a particular distrust incident.
4. Read verify_message only from the real verification exception. Replace non-ASCII
   or non-printable characters, suppress URL/path-like tokens, then truncate to
   100 printable ASCII characters. No str(exc), response text, request URLs,
   authentication data or environment values print. Unknown failures remain unknown.
