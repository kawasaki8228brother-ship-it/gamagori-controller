STREAMING WITHOUT BODY CONSUMPTION
HTTPX 0.28.1 normally awaits redirect-response.aread() even when stream=True.
Simply using client.stream() is therefore insufficient. The response event hook
records first/latest statuses, closes the owned response stream WITHOUT iterating
it, and sets the owned response's empty local _content cache. HTTPX's pinned aread
then takes its no-I/O fast path while retaining status/headers needed for redirects.
No installed package file, app object or production state is modified.
The GET body uses async with client.stream('GET', url), checks status and the closed
empty-cache guard, and never consumes a body iterator. Failure to close/guard is
STOP or an explicitly uncertain observation; never continue with a body fetch.
This guarantees no deliberate HTTP body consumption by the probe. TCP/TLS buffers
can contain coalesced bytes arriving with headers; zero wire receipt of body bytes
cannot be guaranteed by a streaming API. No such bytes or headers are printed.
Local huge-Content-Length/no-body servers and exploding body iterators test this,
including redirects. The observed iterator count is zero; both streams close.

ERROR ATTRIBUTES AND OUTPUT SCHEMA
Per-host rows have separate tls and get objects. No HTTP status manufactures a
Stage-1 TLS verdict. tls.state is CONNECTED, CERT_REJECTED or OTHER_FAILURE;
get.state is HTTP_RESPONSE, CERT_REJECTED or OTHER_FAILURE. Each has an independent
v=PASS/FAIL/UNVERIFIED. The GET object records http (first status), last_http only
when different, and end/error for an incomplete follow-up. First status survives
a blocked redirect; later-hop verification code/message are retained separately.

Only isinstance-based examination of actual SSLCertVerificationError and bounded
__cause__/__context__ chains is used: cycle detection, max 16 nodes/depth 8. The
verify_code is an actual int attribute (bool/string/missing becomes null), and
verify_message comes only from that exception's attribute. Non-printable/non-ASCII
characters and URL/path-like tokens are sanitized, then limited to 100 printable
ASCII characters. str(exc), connection URLs, proxy values, HTTP headers/body,
credentials, process args, environment values and internal paths are never printed.
ProxyError, timeout and DNS errors take priority over nested certificate-looking
errors and remain OTHER_FAILURE. Certificate-looking TEXT alone never qualifies.
Real verification failures with other/missing codes are still recorded distinctly
as CERT_REJECTED; the per-target role, not that label alone, determines acceptance.

When a Stage-1 handshake succeeds, get_verified_chain() may supply the last DER
certificate. Report its SHA-256 only if it is also in the actual context's trusted
DER set; report BAD_ROOTS membership as true/false. Otherwise both values are null.
These are optional diagnostics and never alter the verdict. No unverified chain
is substituted, and no anchor is inferred from the code or from a leaf certificate.
